## 🗺️ 软件栈全景图

```
┌─────────────────────────────────────────────────┐
│                  应用层 (Application)             │
```

## 📦 五个库详解

### 1. CMSIS_5 — ARM 内核接口标准

| 项目 | 内容 |
|------|------|
| **全称** | Cortex Microcontroller Software Interface Standard v5 |
| **来源** | ARM 官方 (github.com/ARM-software/CMSIS_5) |
| **定位** | 最底层 — 直接与 ARM Cortex-M 处理器内核交互 |
| **包含** | Core(M) API、DSP 库、NN 库、RTOS v1/v2 接口、SVD 外设描述 |
| **对 CYT2BL 的作用** | 提供 Cortex-M4F 核心访问：NVIC 中断控制、SysTick 定时器、MPU 内存保护、SIMD 内联函数 |

> ⚠️ ARM 已发布 CMSIS v6，但本项目使用稳定的 v5。

---

### 2. core-lib — Infineon 核心工具库

| 项目 | 内容 |
|------|------|
| **全称** | Core Library |
| **来源** | Infineon (github.com/Infineon/core-lib) |
| **定位** | 工具 / 基础类型层 — 被 HAL 和 PDL 共同依赖 |
| **头文件** | `cy_result.h`（统一返回类型）、`cy_utils.h`（实用宏） |
| **关键内容** | `cy_rslt_t` 结果类型、`CY_ASSERT`、`CY_HALT`、寄存器读写宏 `CY_GET_REG32`/`CY_SET_REG32`、字节序交换、`CY_RAMFUNC` 等 |

> 💡 这个库很小但很关键 — HAL 和 PDL 都依赖它的 `cy_rslt_t` 返回类型和工具宏。

---

### 3. FreeRTOS — 实时操作系统内核

| 项目 | 内容 |
|------|------|
| **全称** | FreeRTOS-Kernel |
| **来源** | FreeRTOS.org (github.com/FreeRTOS/FreeRTOS-Kernel) |
| **版本** | **V11.1.0**（202406.00 LTS 长期支持版） |
| **定位** | 操作系统层 — 可选，不上 RTOS 就不用 |
| **包含** | 任务调度、队列、信号量、互斥量、定时器、事件组、流缓冲区、消息缓冲区 |
| **portable/** | 包含 Cortex-M4F 的移植代码（GCC/IAR/ARM 编译器支持） |

> 💡 CYT2BL3 是双核（M4F + M0+），FreeRTOS 可以跑在一个核或两个核上。

---

### 4. HAL — 硬件抽象层（高级 API）

| 项目 | 内容 |
|------|------|
| **全称** | CAT1 Hardware Abstraction Layer |
| **来源** | Infineon (mtb-hal-cat1) |
| **定位** | **高级抽象层** — 构建在 PDL 之上，提供跨产品线的统一接口 |
| **统一头文件** | `cyhal.h`（包含所有外设驱动） |
| **API 模式** | `cyhal_<peripheral>_init()` / `cyhal_<peripheral>_free()` |
| **CYT2BL3 对应** | **COMPONENT_CAT1A**（与 PSoC 6 同平台） |
| **支持驱动** | ADC、Clock、Comparator、CRC、DAC、DMA、GPIO、I2C、I2S、PWM、QSPI、RTC、SDIO、SPI、Timer、UART、USB、WDT 等 |

> 💡 **HAL 构建在 PDL 之上**（官方确认） — 简单功能直接用 HAL，需要精细控制用 PDL。

---

### 5. PDL — 外设驱动库（低级 API）

| 项目 | 内容 |
|------|------|
| **全称** | MTB CAT1 Peripheral Driver Library |
| **来源** | Infineon (mtb-pdl-cat1) |
| **版本** | **v3.21.1** |
| **定位** | **低级驱动层** — 直接操作外设寄存器，暴露完整硬件功能 |
| **CYT2BL3 器件头文件** | `cyt2bl3bae.h`、`cyt2bl3bas.h`、`cyt2bl3cae.h`、`cyt2bl3cas.h` |
| **包含** | 器件头文件、启动代码、外设驱动 API、SVD 文件 |

> 💡 PDL 的 API 命名风格：`Cy_<Peripheral>_<Function>()`（如 `Cy_GPIO_Write()`）

---

## 🏷️ CAT1A / CAT1B / CAT1C 分类

Infineon 把器件分为三个类别（CAT = Category），代表不同的硬件平台：

| 类别 | 包含器件 | CYT2BL3 归属 |
|:--:|------|:--:|
| **CAT1A** | PSoC 6、**TRAVEO T2G body entry (CYT2BL/2B6/2B7/2B9)**、XMC5000 | ✅ **在这里！** |
| **CAT1B** | PSoC Control C3、AIROC CYW20829 | ❌ |
| **CAT1C** | TRAVEO T2G body high (CYT3/CYT4)、XMC7000 | ❌ |

> 🔑 **CYT2BL3 属于 CAT1A**，与 PSoC 6 共享同一套 HAL 和 PDL 平台实现。CAT1C 是更高端的 T2G 系列（如 CYT4）。

## 🆚 HAL vs PDL — 什么时候用哪个？

| | HAL | PDL |
|------|------|------|
| **抽象层级** | 高（跨产品线统一） | 低（器件特定） |
| **易用性** | ⭐⭐⭐ 简单 | ⭐ 需要读寄存器手册 |
| **功能完整度** | 常用功能 | 全部硬件功能 |
| **代码可移植性** | ✅ 好 | ❌ 差（绑定器件） |
| **Flash 占用** | 较小 | 较大 |
| **API 风格** | `cyhal_gpio_init()` | `Cy_GPIO_Pin_Init()` |
| **适用场景** | GPIO 翻转、UART 收发、I2C 通信 | DMA 链、定时器级联、特殊外设模式 |

> 💡 **经验法则**：先用 HAL 写，遇到 HAL 不支持的功能再降级到 PDL。两者可以在同一个项目混用。

## 📊 依赖关系

```
FreeRTOS ─────────────┐
                       ├──→ core-lib ──→ CMSIS_5 ──→ 硬件
HAL ──→ PDL ─────────┘
```

- **CMSIS_5** ← 被所有人依赖（提供 `core_cm4.h` 等 ARM 标准头文件）
- **core-lib** ← 被 HAL 和 PDL 依赖
- **PDL** ← 被 HAL 依赖（HAL 内部调用 PDL 的 API）
- **FreeRTOS** ← 独立，只需 CMSIS_5 提供 SysTick/PendSV 等
- **HAL 和 PDL** ← 二选一或混用，HAL 是 PDL 的封装
